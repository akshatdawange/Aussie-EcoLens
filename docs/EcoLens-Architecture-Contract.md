## 2. S3 buckets (Member B owns 1–3; Member A owns 4)

| Logical name | Bucket name (in SAM) | Owner | Purpose | Notes |
|---|---|---|---|---|
| originals | `ecolens-originals-${AWS::AccountId}` | B | user uploads land here | triggers orchestrator + thumbnail |
| thumbnails | `ecolens-thumbnails-${AWS::AccountId}` | B | generated previews | publicly readable for UI previews |
| frames | `ecolens-frames-${AWS::AccountId}` | B | video frames | **7-day lifecycle auto-delete** |
| web | `ecolens-web-${AWS::AccountId}` | A | frontend static site | behind CloudFront |

### Object key formats (FROZEN — everyone parses these)
- Original: `{ownerSub}/{fileId}/{filename}`
- Thumbnail: `{ownerSub}/{fileId}/{filenameNoExt}_thumb.jpg`
- Frame: `{ownerSub}/{fileId}/frames/{0001}.jpg`

`ownerSub` = the Cognito `sub`. `fileId` = a UUID generated by `get_upload_url`.

## 3. DynamoDB tables

### 3a. `EcoLensMain` — Member D creates (`infra/data.yaml`); **B writes, D reads**
Single-table design. **Billing mode: `PAY_PER_REQUEST`** (cost rule — never provisioned).

**Key schema + attribute definitions:**
| Key | Attribute | Type |
|---|---|---|
| Base PK | `PK` | S |
| Base SK | `SK` | S |
| GSI1 PK / SK | `GSI1PK` / `GSI1SK` | S / S |
| GSI2 PK / SK | `GSI2PK` / `GSI2SK` | S / S |
| GSI3 PK / SK | `GSI3PK` / `GSI3SK` | S / S |
| GSI4 PK / SK | `GSI4PK` / `GSI4SK` | S / S |

**GSI purposes:**
| Index | PK | SK | Answers |
|---|---|---|---|
| GSI1 | `SPECIES#{name}` | `FILE#{id}` | all files containing a species |
| GSI2 | `THUMB#{url}` | `FILE#{id}` | thumbnail URL → file (reverse lookup) |
| GSI3 | `USER#{sub}` | `CREATED#{iso}` | a user's files, newest first |
| GSI4 | `FEED` | `CREATED#{iso}#{id}` | global newest-first feed |

**Item type 1 — META (one per file). Written by B's orchestrator:**
```
PK            = FILE#{fileId}
SK            = META
fileId        = {uuid}
ownerSub      = {cognito sub}
fileType      = "image" | "video"        # REQUIRED (rubric 2.1.3)
filename      = "koala.jpg"
sha256        = {hex}
originalUrl   = https://ecolens-originals-<acct>.s3.ap-southeast-2.amazonaws.com/{key}   # REQUIRED
thumbnailUrl  = https://ecolens-thumbnails-<acct>.s3.ap-southeast-2.amazonaws.com/{key}  # REQUIRED
tagCounts     = { "koala": 3, "wombat": 1 }   # map
createdAt     = {ISO-8601}
GSI2PK = THUMB#{thumbnailUrl}    GSI2SK = FILE#{fileId}
GSI3PK = USER#{ownerSub}         GSI3SK = CREATED#{createdAt}
GSI4PK = FEED                    GSI4SK = CREATED#{createdAt}#{fileId}
```

**Item type 2 — SPECIES (one per detected species). Written by B's orchestrator:**
```
PK            = FILE#{fileId}
SK            = SPECIES#{species}
species       = "koala"
count         = 3                # number (used for tag-count AND queries)
fileId        = {uuid}
ownerSub      = {sub}
originalUrl   = {same as META}
thumbnailUrl  = {same as META}
GSI1PK = SPECIES#{species}       GSI1SK = FILE#{fileId}
```

> **B↔D agreement:** B writes exactly these attribute names; D's query Lambdas read them.
> If either side renames an attribute, the search breaks. Change here first.

### 3b. `EcoLensHashes` — Member B creates (`infra/pipeline.yaml`)
Deduplication only. `PAY_PER_REQUEST`.
```
PK (HASH) = sha256   (S)
Attributes: fileId, key, ownerSub, createdAt
```

## 6. Inter-service contracts (the exact JSON)

### 6a. `POST /uploads/presign`  (B ↔ A)
**Request:**
```json
{ "filename": "koala.jpg", "sha256": "<hex>", "contentType": "image/jpeg", "fileType": "image" }
```
**Response — new file:**
```json
{ "duplicate": false, "uploadUrl": "<presigned PUT>", "key": "{sub}/{fileId}/koala.jpg",
  "fileId": "<uuid>", "bucket": "ecolens-originals-<acct>",
  "requiredHeaders": { "Content-Type": "image/jpeg" } }
```
**Response — duplicate:**
```json
{ "duplicate": true, "fileId": "<existing>", "key": "<existing key>", "message": "already uploaded" }
```
A then does `PUT {uploadUrl}` with **only** the `Content-Type` header.

### 6b. ML inference `POST {inferUrl}`  (B ↔ C)
- **Request:** raw image bytes as body; headers `Content-Type: image/jpeg` and `X-EcoLens-Secret: <shared secret>`.
- **Response:**
```json
{ "counts": { "koala": 3, "wombat": 1 } }
```
> S3-event mode has no user JWT, so B authenticates to C with the shared secret. C verifies the
> `X-EcoLens-Secret` header. (For `/search/by-image`, D forwards the user's real Cognito JWT instead.)

### 6c. SNS publish (B → D's topic)
B publishes to `/ecolens/sns/tagsTopicArn` with `MessageAttributes.species = [<names>]` so D's
filter policies email only subscribers watching those species.

## 7. Dependency graph

```
A (frontend) ── calls ──▶ B  POST /uploads/presign
A ── calls ──▶ D  query APIs
A ── owns ──▶ Cognito  (C reads pool to verify JWT)

B (pipeline) ── writes items ──▶ D's EcoLensMain      ★ shared schema (§3a)
B ── calls /infer ──▶ C
B ── publishes ──▶ D's SNS topic
B ── reads ──▶ SSM: tables/main, gcp/inferUrl, gcp/sharedSecret, sns/tagsTopicArn

C (ML/GCP) ── reads ──▶ Cognito JWKS (verify tokens)
D (db/api) ── reads items ──▶ EcoLensMain (written by B)
```

### ★ Member B ↔ Member D — shared work (the critical seam)
| Item | Owner / creator | The agreement |
|---|---|---|
| `EcoLensMain` table + 4 GSIs | **D** creates in `infra/data.yaml` | D must deploy this **before** B's orchestrator can write |
| Item shapes (META + SPECIES) | **B** writes, **D** reads | Both follow §3a exactly — attribute names are frozen |
| `EcoLensHashes` table | **B** creates in `infra/pipeline.yaml` | B-only (dedup); D doesn't touch it |
| Table name discovery | D publishes `/ecolens/tables/main` | B reads it from SSM (never hard-codes) |
| Delete flow | D's `DELETE /files` | Removes EcoLensMain rows **and** asks B's buckets to delete objects (or D deletes S3 objects directly with permission) |

**Practical sequence for B+D:** D deploys `data.yaml` → publishes `tables/main` to SSM → B deploys `pipeline.yaml` reading that name → B's mock orchestrator writes a META+SPECIES row → D confirms a query returns it. That round-trip proves the seam.

## 9. Cost rules (real account — protect the bill)
- DynamoDB `PAY_PER_REQUEST` only. API Gateway: prefer HTTP API. CloudWatch log retention 7–14 days.
- `frames` bucket 7-day lifecycle. ECR: keep only latest image. No Lambda provisioned concurrency.
- GCP Cloud Run: scale to zero (no `min-instances` except briefly during the demo).
- Habit: `sam delete` stacks when idle for the day. A `$30` AWS Budget alarm is the backstop.
